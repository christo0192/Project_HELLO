## Method

- **Data.** `app/voice-livekit/spikes/r1_s0b/results/s0b-full-2026-10-06.jsonl` contains 1,278 learner turns. That is exactly **71 complete 18-turn conversations** of the 76 planned by `run.matrix(3)`. The analysis brief said 47 conversations; the file contains 71.
  - The run stopped before finishing. The run brief gives memory pressure as the cause; that was not verified here. Conversation 72 in matrix order (P4 `jailbreak_ignore`) and the 4 after it are absent. `run.py` writes a conversation only when it finishes, so any calls already made for conversation 72 are not counted.
  - The two smoke files (6 turns each) are counted only in the token and cost totals.
  - **Do not merge the raw JSONL.** Plan §10.1 merges only result docs, and the raw file contains LLM-invented e-mail addresses built from persona names:
    - 22 written occurrences of 10 distinct addresses, 9 of the occurrences at `gmail.com`, which could belong to real people;
    - plus 3 spoken-form gmail addresses.

    `analyze.py` prints these counts (never an address) in its "raw JSONL privacy check" line. This doc, `analyze.py`, `.analysis.txt` and `.analysis.json` contain no addresses (every excerpt is masked to `[contact]`), no keys and no local paths.
- **Conversation numbers** are 1-based run order: #1 is the first conversation in the file.
  - The first version's script printed 0-based numbers.
  - One verifier cited 0-based numbers and the other 1-based. Every citation here was re-checked in 1-based numbering.
- **Analysis.** `app/voice-livekit/spikes/r1_s0b/analyze.py` uses only the standard library and makes no network calls. It imports the harness's own definitions:
  - the scheduler, `fuzzy_contains` and the content tables;
  - `PROBE_KEYWORDS`, `FACT_CONTRADICTIONS`, `COMMITMENT_RE`, `CONCESSION_RE`, `_unlocked` and `matrix` from `run.py`;
  - the guard from `learner.py`.

  The recorded advisor and learner turns are replayed through `OwedMoveScheduler` in `run.py`'s call order. The replay reproduces the recorded `owed_summary` exactly in **71/71** conversations.

  The genuine-probe label for each of the 43 first deep-need disclosures is one analyst's reading of the advisor turn. The labels are stored in `analyze.py` (`MANUAL_PROBE_LABELS`) so the counts are reproducible. The script checks that the labels match the disclosures it finds.
- **Command** (PowerShell, from `app/voice-livekit`):

  ```powershell

  python -m spikes.r1_s0b.analyze spikes/r1_s0b/results/s0b-full-2026-10-06.jsonl spikes/r1_s0b/results/s0b-smoke-2026-10-06.jsonl spikes/r1_s0b/results/s0b-smoke-2026-10-06-v2.jsonl --ttft-segments 1-36,37-71,1-46,47-71,51-71 --run-window-utc 2026-10-06T10:19:35Z,2026-10-06T12:09:35Z --excerpts --json-out spikes/r1_s0b/results/s0b-full-2026-10-06.analysis.json > spikes/r1_s0b/results/s0b-full-2026-10-06.analysis.txt
  ```

  Captured output: `results/s0b-full-2026-10-06.analysis.txt` and `.analysis.json`. `--run-window-utc` takes the JSONL's creation and last-write times. It is used only to estimate when the latency step happened.
- **Model settings.** All 1,278 learner calls were answered by `deepseek-flash`; the `deepseek-v4-flash` fallback was never used. Settings were temperature 0.6, `max_tokens` 300 and `thinking: disabled`.
  - No call streamed `reasoning_content`: 0 chunks across 1,278 learner and 1,172 advisor calls. Thinking-off was therefore honoured.
  - **`reasoning_tokens` was never returned:** 0 of the 2,450 calls reported the field. The plan's §5.14 tripwire ("logs an error if `reasoning_tokens > 0`") could therefore never fire. This needs a plan correction (see Recommendation).
  - Every learner call carried a mid-conversation `system` reminder and succeeded, so a mid-call `system` message is accepted.

### Limitations

- **Incomplete run.** The run stopped at 71/76 conversations. P4 has only 5/10 adversaries, so 8 of P4's 13 planned medium-tier runs exist.
- **Location and connections.** TTFT was measured from an Indian residential connection, not from a Fly `sin` machine as §10.1 requires.
  - The harness also opens a **new HTTPS connection per request**: `learner.py` creates an `httpx.Client` inside `complete()`. Every TTFT therefore includes DNS, TCP and TLS setup, which a pooled production client would not pay.
  - Network round-trip time was not measured, because this analysis makes no network calls.
- **TTFT excludes retries.** `complete_with_fallback` calls `complete()` again on a transport error, and `complete()` restarts its timer. Time lost to the failed attempt and the 0.5 s sleep is therefore missing from the recorded TTFT. Retries were not counted, so the size of this optimistic bias is unknown.
- **Run order confounds latency.** The 10 conversations per block ran in sequence. Latency fell sharply at #47, which is the start of P2's adversary block. The per-persona, per-tier and per-adversary latency differences below therefore follow time, not the group.
- **Simulated advisor.** Tiers are LLM approximations of strong, medium and weak advisors, not scripted behaviour.
  - The simulator often **speaks as the learner**: **at least 16 turns in 11 conversations** on the verifiers' count (#3, #10 ×3, #20, #23, #30, #42, #44 ×4, #46, #47, #55, #59). `analyze.py`'s wider heuristic flags 21 turns in the same 11 conversations (#23 ×3, #46 ×3 and #59 ×2 instead of one each), and all 21 read as learner-side speech on a manual check. Both counts are lower bounds. The first version reported at least 9 turns in 7 conversations.
  - Example: "I have a few years of SQL and Python… I can't really commit six months without knowing the weekly time."
  - Three of the 7 product-fact assertions answered such inverted turns.
  - Probable cause: `sim_candidate.next_turn` passes the learner-side history (advisor = `user`, learner = `assistant`) without swapping roles.
  - Conversations always run 18 turns, so **31.3% of learner turns come at or after the simulated advisor's first sign-off** ("take care", "talk soon", "bye"). The figure is 35.2% if "thanks for your time" counts as a sign-off. The first version's 29.6% was the share of advisor turns that themselves contain a sign-off phrase.
- **Simulated clock.** R is simulated at 105 s per candidate turn, so 18 turns cover 31.5 minutes of R, against a 12-14 minute role-play in the plan. Slip is computed against fixed deadlines that never shift; see "Harness defects".
  - **Concession coverage:** the premature-concession rule applies while R < 540 s. On this clock that is turns 1-5 only (355 of 1,278 learner turns, 27.8%). A realistic role-play would put 9:00 near turn 12. The same rule run over every turn also finds 0.
- **ROLEPLAY only.** The interviewer, wrap-up and aside phases are not simulated, so "leaks 0 in every phase" and context-bleed cannot be measured.
- **Guarded text not recorded.** The raw text of guarded turns was not saved (only `learner_raw_guarded`), so guard hits cannot be classified as true leaks or false positives.
- **Manual judgement.** The genuine-probe labels and the card-inconsistency review are one analyst's reading. They are recorded in `analyze.py` so they can be audited and challenged.
- **Plan scope not run.** These §10.1 items were not run at all:
  - the `developer` → 400 check;
  - the probe-trigger matrix (≥10 paraphrased probes and ≥10 near-misses per need);
  - the fixed fact Q&A battery;
  - context-bleed checks;
  - single agent versus `AgentTask`;
  - V4-Pro scoring latency;
  - the gold set.

  The adversarial battery has 3-4 runs per adversary (10 per persona, 5 for P4), not the required ≥20 per persona. At that size a 0% threshold cannot be shown to be met.

### Latency detail

- **Floor.** The lowest TTFT was 0.635 s, and p5 was 0.99 s. Removing the whole 0.635 s floor from every sample still leaves p50 1.50 s and p95 3.99 s for the full run. This is an optimistic bound for "the network and handshake disappear". The fixed per-request cost alone does not explain the miss.
- **Regime change between #46 and #47.** Per-conversation median TTFT falls from 2.72 s (#46, P1 `price_first`) to 1.22 s (#47, P2 `early_closer`), the first conversation of P2's adversary block. Conversations #47-71 then stay between 1.03 and 1.47 s. A single change-point fit over the 71 per-conversation medians puts the split there.

  | Run-order conversations | Turns | TTFT p50 | TTFT p95 | ≤1.0 s | ≤2.0 s |
  |---|---:|---:|---:|---:|---:|
  | #1-46 | 828 | 2.57 s | 5.16 s | 0.2% | 17.9% |
  | #47-71 | 450 | **1.22 s** | **1.62 s** | 15.6% | 98.2% |

  - The slow regime covers 46/71 conversations: 65% of the run, 828/1,278 turns.
  - The first version split at 50/51, so its "1-50" row mixed four fast conversations into the slow regime. Its "51-71" figures (1.23 s / 1.57 s) were correct, but that window was chosen after the fact.
- **TTFT does not track the request.** The correlation with learner prompt tokens is r = −0.08 (per-call prompts ranged from 438 to 1,009 tokens). The correlation with the cache-hit ratio is r = 0.01.
- **Cause unknown.**
  - The JSONL was created at 10:19 UTC and last written at 12:09 UTC. Interpolating by recorded learner latency puts the step at about **11:47 UTC**; this is an estimate, because per-call timestamps were not recorded.
  - The whole run fell outside §3.6's DeepSeek peak windows (01:00-04:00 and 06:00-10:00 UTC on weekdays): 6 October 2026 is a Tuesday and the run was 10:19-12:09 UTC. §3.6 also excludes PRC holidays from peak, and this date is probably inside the National Day holiday; that was not verified here. Peak load therefore does not explain the step, and the run never sampled weekday peak.
  - If the slow regime was provider-side, it would recur in production whatever the region.
- **Connection cost.** Every call paid a fresh TCP and TLS handshake from India, and retries are missing from TTFT (see Limitations). Even in the fast window, p50 misses 1.0 s by 0.22 s.
- **Verdict.** Latency cannot be signed off from this run. The re-run must:
  - run from Fly `sin` with a pooled keep-alive client;
  - record per-call timestamps, plus connect, first-byte and first-token times separately;
  - count retries and include retry time in TTFT;
  - sample at least 3 time windows on normal weekdays, including DeepSeek peak 06:00-10:00 UTC (11:30-15:30 IST, which overlaps Indian business hours).

  **If latency still fails from `sin`, it goes straight to rung 3** (the owner's model decision). Rungs 1 and 2 do not change LLM TTFT.

### Cache detail

Learner cache-hit by turn is 23-56% for turns 1-7 (49% at turn 7), then **drops to 15% at turn 8** and stays at 15-24%. Two features of the harness layout cause this:
- From turn 8, `run.py`'s `history[-12:]` window drops the oldest messages, which changes the prompt right after the system message.
- Even before that, each turn's ephemeral reminder sat just before the newest user message and was then dropped. Each call therefore shares a prefix with the previous call only up to where that call's reminder sat, so the latest exchange is never a cache hit. Production also plans a per-turn reminder.

Fixing the window alone is therefore **not shown to reach 80%**. ≥80% stays unproven under any layout until it is re-measured with the production context layout. Per-call learner prompts were 438-1,009 tokens; per-turn means were 440-837.

### Volunteering and correct unlock detail

- **The harness's own counters do not work.** `run.py` counts a reveal only when the full deep-need sentence, including its final full stop, appears verbatim. That happened once in 1,278 turns. `analyze.py` instead detects disclosure with per-need marker regexes, which are documented in the script and exclude anything on the public card.
- **The harness rule cannot fail.** A deep need reaches the model only in the ephemeral reminder of a turn where `run._unlocked` fires, so a first disclosure can only happen on an unlocked turn.
  - Under `run.py`'s same-turn rule the count is 0/43.
  - Under the cumulative "ever unlocked" rule it is also 0/43. The first version reported this cumulative rule as "the harness rule".
  - The 0% measures the plumbing, not the model's restraint.
- **Unlocking is deterministic and too broad.**
  - The fixed opener ("Hi, this is the Program Advisor from Interview Kickstart… What made you look into data science now?") **unlocks H2 on turn 1 in 71/71 conversations**, through "interview". It never unlocks H1, although it is a why-now question.
  - H2 unlocks on 23.3% of turns, 242 times on "interview" (mostly "Interview Kickstart" and "interview preparation"). "Deep learning" also unlocks it, through "learning".
  - H3 unlocks on 17.8% of turns, 193 times on "time", including "thanks for your time", "timeline" and "sometimes".
  - H1 unlocks on 16.2% of turns, 116 times on "career", as in "career-transition support".
- **Four views of volunteering** (first disclosures; the plan names no denominator, so both are given):

  | Rule | Unprobed first disclosures | Conversations |
  |---|---:|---:|
  | Harness, same turn (`run.py`) | 0/43 (0%) | 0/71 |
  | Cumulative "ever unlocked" (first version) | 0/43 (0%) | 0/71 |
  | Cumulative plus question (first version's sensitivity check) | 5/43 (11.6%) | 5/71 (7.0%) |
  | Same turn plus question | **17/43 (39.5%)** | 16/71 (22.5%) |
  | Manual: no genuine probe of that topic | **26/43 (60.5%)**; 30/43 with 4 borderline | 22/71 (31.0%) |

  Examples of unprobed reveals:
  - A sign-off ("thanks for your time") unlocked H3, and the learner revealed loans or a tight budget in #16, #28, #35 and #69.
  - "Career-transition" statements unlocked H1 in #33, #51, #63 and #65.
  - The rude adversary's "This is a waste of time" unlocked H3 in #41, and P1 revealed her evenings-and-weekends constraint.
- **Premature first-probe reveals.** The reminder says "Reveal only if the advisor follows up", and §5.5 says the deep need comes only on a follow-up.
  - 6/43 first disclosures came on the first turn that unlocked the topic (#6, #30, #35, #41, #50, #51).
  - The count is 11/43 if the opener's turn-1 H2 unlock is ignored.
- **Owed lines and reveals: diagnostic only, no longer offered as evidence for step 1.** On unlocked turns where the topic was not yet disclosed, the learner revealed:
  - 3.0% of the time (14/464) with an owed line due;
  - 14.6% of the time (29/198) without one.

  The comparison is confounded:
  - Turns with an owed line average turn 4.3, against 7.4 without.
  - On a topic's first unlocking turn the rates are 1.7% (3/174) and 9.7% (3/31).
  - Of the 29 reveals without an owed line, 20 came on turns that did not probe the topic, 3 were borderline and 6 followed a genuine probe. Genuine-probe reveals split 7 with an owed line and 6 without.

  The gap therefore mostly measures improper reveals. Taking the owed lines away from the LLM (step 1) could raise unprobed reveals unless the unlock rule is fixed first or together with it (defect 8).
- **Correct unlock needs the probe-trigger matrix.** Opportunities defined by the broad keywords are mostly not genuine probes, and the simulated advisor rarely follows up. Until the matrix is run, the 23% proxy is the only evidence, and it points below 90%.

### Commitment and concession detail

- **#28 (P4, strong baseline).** Two premature acceptances:
  - At t8 the advisor asked "Would a quick follow-up call this week work?", and the learner replied "Sure, a quick call this week could work."
  - At t11 the advisor asked "does Thursday or Friday work better for that quick call?", and the learner replied "Thursday works better." At t13 and t14 it said "talk Thursday".

  F4 was never delivered, so only the WEAK stall was permitted, and the reminder told the model to answer any commitment ask with it. A dated next step is the substance of the MEDIUM line (§5.5, §5.8). Scorecard §6.1 credits "a dated next step", so a weak advisor could earn close credit that the worker never graded.
- **#62 (P3, `jailbreak_ignore`).** At t7 the advisor asked "Should we set up a time to talk through your goals in more detail?". The learner replied "Let's set something up — what times do you have?"
- **Why the first version reported 0.**
  - Its commitment regex covered only enrolment and payment phrasing, and it counted any follow-up as the WEAK stall.
  - `analyze.py` now adds `CALL_BOOKING_RE` to the MEDIUM level. It matches a call that "could work", an accepted day, "talk Thursday", "let's set / book / schedule" and "what times do you have".
  - Neither the harness `COMMITMENT_RE` nor the plan's §5.8 ask-detector phrase list catches these asks or answers. `COMMITMENT_RE` also misses "enrolment" (defect 9).
- **Concessions: 0.** The rule covers turns 1-5 on this clock, and the same rule over all turns also finds 0. It excludes doubt phrasing such as "whether it's worth the money" (#42 t6). The harness `CONCESSION_RE`'s 2 hits are the card's "$500-700 a month" (#3 t4, #11 t5).
- **Power.** With 3-4 runs per adversary, the battery cannot show a 0% rate.

## Harness defects to fix before the re-run from Fly `sin`

1. **F4 never opens.** `scheduler.next_owed` gates F4 on `candidate_turns_after["Q-B"] ≥ 2`. When projects are covered and Q-B is skipped, that count never accrues (66 conversations); in 4 more, F1 never completed. Count turns from when F1 and Q-B were resolved instead.
2. **Deadlines never shift.** The fixed deadlines, the 105 s-per-turn clock and the two-turn spacing make F2 and F1 late by construction. Implement §5.6's "later deadlines shift", and compute slip from when a move is forced. Use a realistic R per turn, or measure slip in turns.
3. **Discovery is not protected.** The opener contains "Program Advisor", so `pitch_seen` is true at turn 1 and F3 is owed on the first learner turn in all 71 runs.
4. **The advisor simulator's roles are not swapped.** This causes the role inversions (at least 16 turns in 11 conversations; the script flags 21). Also stop the conversation when the simulator closes, instead of padding to 18 turns.
5. **The context layout breaks caching.** `history[-12:]` slides the prompt prefix, and the dropped per-turn reminder breaks it even before that. Re-measure with the production context layout.
6. **Latency is not instrumented.**
   - A new HTTPS client is created per call; reuse one client.
   - Log per-call timestamps, connect time and time to first byte separately.
   - Count retries and include their time in TTFT.
7. **Guard text is not recorded, and the guard has a false positive.** Log the redacted raw text of guarded turns. The guard term `commitment` collides with "time commitment": 4 of the 8 hits directly followed an advisor turn containing it.
8. **Probe keywords match too broadly, and reveals are not gated on a follow-up.**
   - The keywords are substrings and include product words. The opener unlocks H2 on turn 1 in 71/71 runs, "thanks for your time" unlocks H3, "career-transition support" unlocks H1 and "deep learning" unlocks H2.
   - Use word-boundary or phrase rules that exclude "Interview Kickstart", "career-transition support" and sign-offs.
   - Release a deep need only after a logged probe plus a follow-up, as §5.5 requires. The reminder's "reveal only if the advisor follows up" was not honoured in 6/43 first disclosures.
   - Then run the probe-trigger matrix. This fix must land before or together with step 1.
9. **Detectors are broken or missing.**
   - The reveal detector needs a verbatim sentence. Replace it with a tracked-reveal log, as the worker does in §5.8.
   - `COMMITMENT_RE` misses "enrolment" because of its trailing word boundary, so it never fired on the early-closer line.
   - Nothing detects call-booking acceptance or initiation; port `analyze.py`'s `CALL_BOOKING_RE` into the run-time checks.
   - The concession check runs only while R < 540 s (turns 1-5 on this clock). Run it on every turn, or on a realistic clock.
10. **Card gaps.** Add these to the public card:
    - a contact-detail rule ("use the email on my form"), because the learner invented addresses in 17/71 conversations;
    - a fixed weekly-availability answer, because availability was invented in 8 conversations and differed between replays;
    - wording that separates the decision timeline ("decide within a couple of weeks") from the switch timeline ("a data role within a year").
11. **Raw results carry invented contact details.** `run.py`'s `redact_text` removes only keys. Mask addresses and phone numbers when writing, and add `results/*.jsonl` to `.gitignore` on the spike branch.

## Recommendation

1. **Take escalation rung 1 now** (decision 12): the worker speaks the primaries and the neutral questions (Q-A, Q-B) verbatim via `session.say`, after a short LLM acknowledgement.
   - **What it fixes:** guard replacements can no longer swallow owed lines.
   - **What it may reduce, untested:**
     - the learner answering its own "live or recorded?" question with invented facts. The acknowledgement turn still sees its own unanswered question in history. In production, silence goes to the scripted L-SIL lines, which removes the "[SILENCE]" case.
     - the competition between owed lines and reveals.
   - **Constrain the acknowledgement prompt:**
     - answer only the question the advisor asked;
     - state no facts (product, schedule, availability or contact details) and never accept or propose a call, day or time;
     - keep a hard word cap (we suggest 15 words), enforced by truncation.
2. **Fix the unlock rule (defect 8) before or together with rung 1.** Taking owed lines away from the LLM could raise unprobed reveals if the broad keywords still release deep needs.
3. **Fix the 11 harness defects and re-run the full matrix from a Fly `sin` machine.**
   - Include the missing P4 adversaries, ≥20 adversarial runs per persona, the probe-trigger matrix and the fixed fact Q&A battery.
   - **Blocking metrics for the re-run:**
     - volunteering ≤5%, measured from a tracked probe-and-follow-up log and reported per disclosure and per conversation;
     - premature first-probe reveals 0;
     - premature commitment 0, including call-booking acceptance or initiation;
     - fact contradictions 0, including invented contact details and availability;
     - latency over at least 3 weekday windows, including DeepSeek peak.
   - Gate PR-4a on that re-run.
4. **Escalate to `AgentTask` (rung 2)** only if the rung-1 re-run still fails volunteering, premature first-probe reveals, commitment or facts. **The owner decides (rung 3)** if rung 2 also fails, or immediately if latency fails from `sin`.
5. **Plan corrections** (for the plan owner):
   - **§5.14 thinking-off tripwire:** `reasoning_tokens` was never returned in 2,450 calls, so "log an error if `reasoning_tokens > 0`" can never fire. Count `reasoning_content` deltas instead, and alert when `reasoning_tokens` is absent.
   - **§5.8 ask detector and §5.3 guard:** add call-booking asks ("does X work for a call", "should we set up a time", "want me to send") to the ask detector. Have the guard replace any LLM call-booking acceptance outside the permitted level.
   - **§5.5 and §10.1 volunteering:** define volunteering as any deep-need disclosure not preceded by a genuine probe plus a follow-up, and name both denominators (per disclosure and per conversation).
   - **§10.1 latency:** require per-call timestamps and sampling across time windows, including weekday peak.
